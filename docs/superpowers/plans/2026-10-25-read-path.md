# Scoped Read Path Implementation Plan

> **For agentic workers:** Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox syntax for tracking.

**Goal:** Reduce authorization query amplification and fetch only the revision snapshots required by change review.

**Architecture:** Request-local authorization closures share one grant read and timestamp. A scoped exact-revision lookup flows through the existing HTTP/SDK/MCP boundary into the current review screen.

**Tech Stack:** Node.js >=22.13, TypeScript, better-sqlite3, Fastify, React, Zod, Node test runner, Playwright.

**Spec:** `docs/superpowers/specs/2026-10-25-read-path-design.md`

## Global Constraints

- Keep the MIT license and all repository-authored text in English.
- No database migration or added dependency.
- Preserve existing routes, SDK methods, and MCP tool contracts.
- Default deny, deny precedence, scope boundaries, current revocation and expiry remain enforced.
- Apply authorization is evaluated inside the existing immediate transaction.

## Review Focus

- A cached identity or grant must not survive into another request.
- Wrong-path and cross-workspace revision IDs must not reveal content.
- Historical revision reads must fail after permission revocation or expiry.
- Stale or failed snapshot responses must not enable approval or replace another proposal's content.
- Query-count improvements must be accompanied by real permission/returned-content assertions.
